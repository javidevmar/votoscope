# Skills (optional)

The harness does not vendor third-party skills. Put project-specific OpenCode
skills in this directory, or install them with your skills manager.

Useful capabilities for this workflow:

- **Harness CLI** — `harness-cli/SKILL.md` explains init, sync and doctor, with
  copy-only install safety and verification.
- **Spec Driven Development** — EARS, requirements, design, tasks.
- **Test Driven Development** — red, green, refactor.
- **Debugging and error recovery** — reproduce, isolate, fix, verify.
- **Git workflow and versioning** — branches, atomic commits, stacked PRs.
- **Code simplification** — delete before adding; stdlib before dependencies.
- **Context engineering** — keep the constitution and topic docs current.

A skill is not a rule. The constitution (`AGENTS.md`), the process
(`.agents/specs.md`) and the project docs are authoritative; skills are
orientation.
